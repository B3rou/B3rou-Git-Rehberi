## 1. Kurulum ve Ayarlar (Config)

Git'i kurduktan sonra **sadece bir kez** yapman gereken kimlik ayarları.

| Komut | Açıklama |
| --- | --- |
| `git config --list` | Mevcut ayarları listeler. |
| `git config --global user.name "İsim"` | Commitlerde görünecek ismini ayarlar. |
| `git config --global user.email "mail"` | Commitlerde görünecek mailini ayarlar. |
| `git config --global core.autocrlf true` | **Windows:** Satır sonu karakterlerini (CRLF) düzeltir. |
| `git config --global core.autocrlf input` | **Mac/Linux:** Satır sonu karakterlerini (LF) düzeltir. |
| `git config --global init.defaultBranch main` | Varsayılan dal ismini `main` olarak sabitler. |

---

## 2. Başlangıç (git init)

Bir projeyi Git takibine almak için kullanılır.

| Komut | Açıklama |
| --- | --- |
| `git init` | Bulunduğun klasörde `.git` klasörü oluşturur ve takibi başlatır. |

---

## 3. Muhteşem Döngü (The Cycle)

Günlük hayatta en çok kullanacağın komutlar.

| Komut | Açıklama |
| --- | --- |
| `git status` | **Pusula.** Hangi dosya değişti? Hangi dosya sahneye alındı? |
| `git add <dosya>` | Belirtilen dosyayı **Staging Area**'ya (Sahneye) ekler. |
| `git add .` | Tüm değişiklikleri (yeni, değişen, silinen) sahneye ekler. |
| `git commit -m "mesaj"` | Sahnedeki dosyaları kalıcı olarak **Repo**'ya kaydeder (Fotoğraf çeker). |
| `git log` | Projenin tarihçesini (Commit geçmişini) gösterir. |

> [!TIP]
> **Madem buraları okuyorsun, o zaman sana bir Pro Tip**: <br>
> * `git log --oneline` yazarak loglarını tek bir çizgide görebilirsin. <br>
> * `git log --graph --oneline --all` gibi komutlar ile argümanı arttırarak grafiği özelleştirilebilir, daha havalı grafikler elde edebilirsin! <br>

> [!TIP]
> **Pro Tip'in Pro Tipi:** <br>
> * Eğer bu uzuuuun komutu hatırlamak ve yazmak istemiyorsan git sana yardımcı oluyor. Bu özelliğe daha sonra detaylıca değineceğiz, ama hadi biraz eğlenelim: <br>
> * `git config --global alias.tree "log --graph --oneline --all"` komutunu gir, artık git tree yazdığın zaman git, bu uzun komutun çıktısını sana verecek! <br>
> * Git sana düşman değildir, her zaman power user olmana kapı bırakır. Ne hoş değil mi?

## 4. Gizleme (.gitignore)

Gereksiz dosyaları Git'ten uzak tutmak.

* **`.gitignore` Dosyası:** İçine yazılan dosya veya klasör isimleri Git tarafından *asla* görülmez.
* Örnek: `*.log`, `node_modules/`, `.env`



| Komut | Açıklama |
| --- | --- |
| `git rm --cached <dosya>` | Dosyayı silmeden, sadece Git takibinden (sahneden) çıkarır. |

---

## 5. Bölümde Geçen Kavramlar Sözlüğü

> [!TIP]
> Ezberlemekle didinmeyin, çünkü zamanla zaten ağzınıza yerleşecekler. Unuttuğunuzda buraya bakmanız yeterli olacaktır.

* **Repository (Repo):** Projenin veritabanı (`.git` klasörü).
* **Commit:** Projenin o anki halinin fotoğrafı (Snapshot). Her commit'in eşsiz bir kimliği (SHA-1) vardır.
* **Staging Area (Index):** Kargo paketleme masası. Commit'lemeden önceki hazırlık alanı.
* **Working Directory:** Senin çalışma alanın, dosyaların olduğu yer.
* **Hash (SHA-1):** Her commit'e özel üretilen 40 karakterlik benzersiz kimlik kodu. (Örn: f71f80d).
* **Untracked File:** Klasörde duran ama Git'in henüz "add" komutuyla tanışmadığı dosya.
* **Tracked File:** Git'in takip ettiği dosya. (Yani en az bir kez `git add` ile sahneye alınmış dosya).
* **Modified File:** Değiştirilmiş ama henüz sahneye alınmamış dosya.
* **Staged File:** Sahneye alınmış ve bir sonraki commit'e dahil edilecek dosya.
* **Main Branch (veya Master):** Projenin ana zaman çizelgesi (branch).
* **Root:** Projenin en dış klasörü (ana dizin).
* **Line Endings:** Satır sonlarında kullanılan görünmez karakterler. (Windows: CRLF, Mac/Linux: LF)

> [!NOTE]
> Alttaki kelimeler bu bölümde yalnızca isim olarak geçti ama anlatımı [Bölüm 2, Multiverse](../2-multiverse/)'de yapacağım. <br>
> Yine de bir ön bilgi olarak buraya bırakıyorum:

* **Branch:** Paralel evrenler. Aynı anda birden fazla zaman çizelgesi oluşturma.
* **Merge Conflict:** İki farklı dalda (branch) yapılan değişikliklerin çakışması durumu.
