# 2.3 - Alternatif Gerçeklikler: Orphan Branch ve Temizlik 🧹

> *"Bazen geçmişi düzeltmek yetmez; geçmişi hiç olmamış gibi yepyeni bir sayfa açmak gerekir."*

Gelişmiş branch yönetiminden (Rebase, Cherry-Pick) sağ çıktığına göre, artık paralel evrenlerin son sırrına geçebiliriz: **Geçmişi olmayan branch'ler (Orphan Branches)** ve işi biten dalları yok etme sanatı.

Bu bölüm, zihnini dinlendirecek kısa bir mola ve aynı zamanda reponun bahar temizliği olacak.

---

## 1. Kökü Olmayan Ağaç: Orphan Branch 🌱

Şimdiye kadar oluşturduğun her branch, koptuğu yerin (genellikle `main`) tüm geçmişini ve commitlerini miras alıyordu. Peki ya **tamamen boş, hiçbir geçmişi (tarihçesi) olmayan**, yepyeni bir branch yaratmak istersen?

İşte buna `orphan` (öksüz/yetim) branch denir. 

**Neden İhtiyacımız Olur?**
* Projenin kodlarıyla hiç alakası olmayan, sadece dokümantasyon barındıran bir web sitesi (`gh-pages`) branch'i oluşturmak için.
* Aynı repo içinde tamamen bağımsız, sıfırdan başka bir projeye başlamak için.

### Hadi Deneyelim

Sıfır kilometre, tertemiz bir geçmişe sahip bir branch oluşturalım:

```bash
git switch --orphan yepyeni-sayfa
```

> **Terminal:** *"Switched to a new branch 'yepyeni-sayfa'"*

Şimdi `git log` yazmayı dene. Git sana hata verecek! Çünkü bu branch'te **henüz hiçbir commit (geçmiş) yok.**

Klasörüne (Çalışma Alanına) bir bak. Eski branch'teki (`main`) dosyaların Git tarafından otomatik olarak temizlendiğini göreceksin. Artık yeni bir dosya oluşturup bu yepyeni branch'i başlatabilirsin:

```bash
echo "Burası yepyeni bir proje" > ilk-mesaj.txt
git add .
git commit -m "init: orphan branch baslangici"

```

> [!NOTE]
> `git switch --orphan` komutu sadece Git'in önceden takip ettiği (Tracked) dosyaları temizler. Eğer klasöründe daha önceden takip edilmeyen (Untracked) veya `.gitignore` içinde olan dosyalar varsa, bunlar yeni branch'e de gelir. Çalışma alanını bu untracked dosyalardan da tamamen arındırmak istersen `git clean -fdx` komutunu kullanabilirsin.

👉 *Şimdi `git tree` yap. Bu yeni branch'in, diğer branch'lerle hiçbir bağının olmadığını, havada asılı durduğunu göreceksin.*

---

## 2. Bağımsız Geçmişleri Merge Etmek 🔗

Bu köksüz (orphan) branch'i alıp, `main` branch'ine standart bir şekilde merge etmek istersen Git sana şu hatayı verecektir: `fatal: refusing to merge unrelated histories`.

Çünkü Git, ortak bir atası (parent) olmayan iki farklı projeyi yanlışlıkla merge ettiğini sanır. Bu güvenlik duvarını aşıp branch'leri bilinçli olarak birleştirmek istersen şu parametreyi kullanmalısın:

```bash
git switch main
git merge yepyeni-sayfa --allow-unrelated-histories
```

*(Not: İki branch'te de aynı isimde dosyalar varsa conflict yaşanabilir, bunları her zamanki gibi editöründen çözebilirsin.)*

---

## 3. Bahar Temizliği: Branch'ler Nasıl Silinir? 🗑️

Branch açmak maliyetsizdir, ancak işi biten (merge edilmiş) branch'leri ortalıkta bırakmak reponu kalabalıklaştırır. Proje (veya özellik) bittiğinde o branch'i silmelisin.

Şu an zaten `main` branch'indeyiz ve `yepyeni-sayfa` branch'ini başarıyla merge ettik. Artık ona ihtiyacımız yok.

**Silme İşlemi:**
*(Üzerinde bulunduğun branch'i silemezsin, bu yüzden main'de kalmaya devam et)*

```bash
git branch -d yepyeni-sayfa
```

> **Terminal:** *"Deleted branch yepyeni-sayfa (was a1b2c3d)."*

Puf! O branch artık yok. Git, bu işlemi sorunsuz yaptı çünkü içerideki tüm değişikliklerin `main`'e güvenle aktarıldığını (merge edildiğini) biliyordu.

<details>
<summary>🛡️ Merge Edilmemiş Bir Branch Nasıl Silinir? (-D)</summary>

Eğer bir branch'te çalıştın ama sonra fikrinden caydın (projeyi iptal ettin) ve **hiç merge etmeden** silmek istersen, küçük `-d` parametresi hata verir. Git seni korumak için *"Bu çalışmayı henüz hiçbir yere aktarmadın, silersen kaybolur!"* der.

Eğer gözünün yaşına bakmadan, zorla silmek istersen büyük `-D` (Force Delete) kullanmalısın:

```bash
git branch -D iptal-edilen-branch
```

</details>

> [!TIP]
> **Altın Kural:** Merge işlemi biten branch'leri `git branch -d <branch_ismi>` ile düzenli olarak silmeyi alışkanlık haline getir. Hem lokal bilgisayarın temiz kalır hem de `git tree` grafiğin bir spagettiye dönüşmez.
